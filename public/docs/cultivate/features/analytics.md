## 1. 概要

### 1.1 機能の目的

サーバーの統計データを**自動収集・集計**し、**グラフで可視化**する機能です。
既存の「性別比率の折れ線グラフ」を起点に、以下のデータを扱えるよう拡張します。

- 性別比率の時系列推移
- メンバー数・新規参加・退会の時系列推移
- 日次アクティビティ（メッセージ/リアクション/VC/アクション人数）の推移
- 期間ランキング（話しかけ王・リアクション王・絵文字）
- 招待リンク別参加者数
- ランクシステム連携による活動量分析
- チャンネル別・ロール別のデータ閲覧
- カスタム期間指定（○月○日〜）によるランキング集計

### 1.2 既存資産の棚卸し

| 資産 | 場所 | 現状 |
|---|---|---|
| `/analytics` コマンド | `cmds/analytics_cmd.py` | `性別` のみ対応・管理者限定・特定ギルド（MP）固定 |
| グラフ描画 | `utils/plot.py` | matplotlib 折れ線グラフ・日本語フォント未対応 |
| 性別スナップショット | `database.py` `users` テーブル | `save_sex_info()` が日次記録 |
| システムコグ置き場 | `utils/system_cogs/analytics_cog.py` | **空ファイル（実装予定地）** |
| 日本語フォント | `data/fonts/` | meiryo.ttc / msgothic.ttc / YuGothM.ttc |

### 1.3 用語定義

| 用語 | 説明 |
|---|---|
| **指標（メトリクス）** | 表示するデータの種類。性別・メンバー数・ランク・投稿数など |
| **スナップショット** | ある時点の集計値を DB に保存した記録 |
| **自動記録** | 毎日 00:05（JST）にサーバーの現状（性別構成・総メンバー数・参加/退会・日次アクティビティ）を自動保存すること。時系列グラフのデータ源となる |
| **アクション人数** | その日に1回以上「何らかのアクション（メッセージ投稿・リアクション付与・VC参加）」をしたユニークメンバー数。内訳としてメッセージ人数・リアクション人数・VC参加人数を持つ |
| **期間ランキング** | 指定期間（今週/先週/今月/先月）内の累計値を集計し、大きい順にユーザーや絵文字を並べた表（話しかけ王・リアクション王・絵文字ランキング） |
| **時系列グラフ** | 日付を横軸、数値を縦軸にした折れ線グラフ |
| **ランキング** | 数値の大きい順にユーザーやチャンネルを並べた表 |

### 1.4 データ保存期間ポリシー

サーバーの登録形態によって、保存期間を切り替えます。

| 登録形態 | 保存期間 | 対象サーバー |
|---|---|---|
| **プレミアム（有料登録）** | **全期間保存** | `premium = true` |
| **無料** | **90日間保存**（超過分は自動削除） | `premium = false`（デフォルト） |

- 毎日 00:05（JST）の記録タスク内で、無料サーバーの**90日超過データを自動削除**
- 削除対象テーブル: `analytics_snapshots` / `analytics_user_daily` /
  `analytics_emoji_daily` / `analytics_channel_posts` /
  `analytics_role_posts` / `analytics_role_members`
- `analytics_invites` は累計値のため削除しない

#### プレミアム判定の仕組み

`analytics_settings.settings_json` の `premium` フラグで管理します。
付与方法は以下の優先順位とします。

1. **`Var.PREMIUM_GUILD_IDS` の鯖は常に `premium = true`**
   （起動時・初回設定作成時に自動付与）
2. **それ以外の鯖は初期値 `false`**
3. **Premium登録コグ**（新規システムコグ `premium_cog.py`）の登録操作で
   `true` に変更可能

> **現時点の `Var.PREMIUM_GUILD_IDS`**: Labo / DeLien / dev の3鯖（2026-08-09時点）
>
> 課金・決済連携は本Botのスコープ外とし、Premium登録コグの実装で対応します。
> アナリティクス側はフラグを**読み取るだけ**で、付与処理には依存しません。

## 3. 詳細仕様

### 3.1 性別比率（A-01）

#### データ収集

従来の `function.py save_sex_info()` は **Var 固定のロールID**（MPギルド専用）でした。
これを**ギルドごとに設定可能**な方式へ変更します。

```
設定例（サーバーごと）:
  男性ロール:   [🚹 男性, 男ロール]
  女性ロール:   [🚺 女性, 女ロール]
  LGBTQロール: [🏳️‍🌈 LGBTQ]
```

- 対象メンバー = 各ロールを所持しているメンバー（Bot は除外）
- どのロールにも該当しないメンバーは「未設定」として集計

#### 性別集計モード（M-02）

複数性別ロール所持者の扱いは、サーバーごとに**設定で切り替え**られます。

| モード | 集計対象 | 重複カウント | 想定用途 |
|---|---|---|---|
| `men_women`（男女のみ・デフォルト） | 男性・女性ロールのみ | **禁止**（複数所持者は先勝ちで1回のみ） | 男女の区分を明確にしたいサーバー |
| `men_women_lgbtq`（男女+LGBTQ） | 男性・女性・LGBTQ ロール全て | 可（男女とLGBTQは別軸として両方に含める） | LGBTQロールを性別ロールに追加で取得したいサーバー |
| `lgbtq_only`（LGBTQのみ） | LGBTQ ロールのみ | — | LGBTQのみを別途把握したいサーバー |

> モード `men_women_lgbtq` での重複は「男性＋LGBTQ」のように**別分類間**に限ります。
> 同一分類内（例: 男性ロールを2つ所持）は1人として数えます。

#### スナップショット保存

- 毎日 **00:05（JST）** に自動記録（`discord.ext.tasks` のループ）
- 手動実行コマンドも用意（設定変更後の即時記録用）

#### グラフ表示

- 横軸: 日付、縦軸: 人数
- 男（青）・女（赤）・LGBTQ（紫）・合計（緑）の4本の折れ線
- 日本語フォント（`data/fonts/meiryo.ttc`）でラベル・凡例を表示
- データが多い場合は間引き（既存の `plot.py` の仕組みを踏襲）

### 3.2 メンバー数推移（A-02 / S-02）

- 毎日 00:05（JST）に `len(guild.members)` を記録
- 記録テーブルは性別スナップショットと共通化（指標種別で区分）
- グラフは総メンバー数の単一折れ線

### 3.3 ランクXPランキング（A-03）

`rank_cog_user_exp` テーブルから集計:

| 項目 | ソース |
|---|---|
| chat EXP | `rank_cog_user_exp.chat_exp` |
| inchat EXP | `rank_cog_user_exp.inchat_exp` |
| vc EXP | `rank_cog_user_exp.vc_exp` |
| 合計 | 3系統の合計 |

- アクティブプリセット（`rank_cog_active_presets`）を対象にする
- TOP10 を Embed で表示
- グラフは棒グラフ（ユーザー名 × EXP）

### 3.4 期間別活動量比較（A-04）

`rank_cog_period_exp` テーブルから集計:

- `period_type`（週間/月間）と `period_key` で絞り込み
- 指定した期間（今週/先週、今月/先月）の合計EXPを比較
- グラフは棒グラフ（期間 × EXP）

### 3.5 チャンネル別投稿数（A-05）

**初回リリースに含めます**（依頼者確認済み）。

- `on_message` イベントでテキストチャンネルごとの投稿数を日次カウント
- Bot・コマンド（`!` `/` 始まり）は除外
- 集計結果はランキング表示（TOP10）
- **削除されたチャンネルも閲覧できるよう、`channel_id` と一緒に `channel_name` を記録**する
  （チャンネル名は日次確定時点の名前を保存）

> **注意**: 全メッセージを永続保存すると容量が膨らむため、
> 日次の**集計値のみ**を保存する方式とします。
> この指標は自動記録（00:05）ではなくイベント駆動でカウントし、
> 毎日 00:05 に前日分を確定保存します。

### 3.6 新規参加・退会人数（A-06 / A-07 / S-03）

- `on_member_join` で日次参加カウント +1（**一度抜けた人の再参加も含む**）
- `on_member_remove` で日次退会カウント +1
- 毎日 00:05（JST）に前日の参加数・退会数を DB へ確定保存
- グラフは「参加」「退会」の2本の折れ線（または棒グラフ）

> イベントログ（誰がいつ参加したか）は保存せず、**日次の人数のみ**を保存します。
> 退会者はキャッシュから消えるため、`on_member_remove` のタイミングで
> カウントだけ行う方式です。

### 3.7 日次アクティビティ人数（A-08〜A-11 / S-04）

「その日に1回以上アクションしたユニーク人数」を日次で記録します。

| 指標 | 判定イベント | 内容 |
|---|---|---|
| メッセージ人数（A-08） | `on_message` | その日に1回以上メッセージを投稿したユニーク人数 |
| リアクション人数（A-09） | `on_reaction_add` | その日に1回以上リアクションを**付与**したユニーク人数 |
| VC参加人数（A-10） | `on_voice_state_update` | その日に1回以上 VC に**接続**したユニーク人数 |
| アクション人数（A-11） | 上記すべて | メッセージ・リアクション・VC の**いずれか**1回以上したユニーク人数 |

- Bot・コマンド（`!` `/` 始まり）は除外
- メモリ上で日次ユニーク集合（`set[user_id]`）を管理し、00:05 に人数を確定保存
- グラフは各指標を1本ずつ折れ線表示（または複数本を重ねて表示）

> この指標は「人数」であり投稿数・リアクション**回数**ではありません。
> 回数ベースの集計は 3.8 の期間ランキングで扱います。

### 3.8 期間ランキング（A-12〜A-14 / S-05）

指定期間（今週/先週/今月/先月）内の累計値をランキング表示します。

| ランキング | 記録するイベント | 集計内容 |
|---|---|---|
| 話しかけ王（A-12） | `on_message`（メンションあり） | 期間内に**メンションした回数**が多いユーザー順 |
| リアクション王（A-13） | `on_reaction_add` | 期間内に**リアクションした回数**が多いユーザー順 |
| 絵文字ランキング（A-14） | `on_message`（絵文字あり） | 期間内に**使用された回数**が多い絵文字順 |

- ユーザー・絵文字ごとの日次回数をメモリで集計し、00:05 に日次確定保存
- 期間集計は保存済み日次データを SUM して算出
- 絵文字は `emoji_id`（カスタム）と `emoji_text`（ユニコード）を分けて記録し、
  **カスタム絵文字が削除されても名前・IDが残る**ように `emoji_name` も保存
- 表示は TOP10 の Embed（絵文字ランキングは使用回数＋絵文字表示）

#### 期間の指定方法

| 指定方法 | 引数 | 例 |
|---|---|---|
| プリセット期間 | `期間: 今週/先週/今月/先月` | `期間=今週` |
| **カスタム期間** | `開始日`・`終了日`（両方任意） | `開始日=2026/07/01 終了日=2026/07/31` |

- `期間=カスタム` を選んだ場合、`開始日`・`終了日` を指定して集計
- 開始日のみ指定（終了日省略）なら開始日〜今日まで
- 終了日のみ指定（開始日省略）なら保存開始〜終了日まで
- 保存期間を超えた過去日を指定した場合は、存在するデータのみで集計
  （無料サーバーは最古で90日前まで）

### 3.9 招待リンク別参加者数（A-15 / S-06）

- `guild.invites()` の差分方式で、参加時に使われた招待リンクを特定
  - 起動時（`on_guild_available`）に全招待リンクをキャッシュ
  - `on_member_join` で再取得し、前回より**カウントが増えたリンク**を
    その参加に使用されたリンクと判定
  - 増加リンクが特定できない場合（Vanity URL・招待なし等）は「不明」として集計
- 招待リンクごとの累計参加者数を表示（リンクコード・招待者名・参加者数）

> 招待リンクは削除・期限切れがあり得るため、`invite_code` と一緒に
> **招待者名** を記録して、リンクが消えても閲覧できるようにします。

### 3.10 チャンネル別・ロール別のデータ閲覧

#### チャンネル別

- チャンネル別投稿数（A-05）に加え、チャンネルごとの時系列グラフも閲覧可能
- 対象はテキストチャンネル。**削除済みチャンネルも `channel_name` 記録により閲覧可能**
- 表示時はチャンネル選択（`ChannelSelect`）で絞り込み

#### ロール別

- ロールごとの**所持メンバー数の日次推移**を記録・閲覧可能
- ロールごとの**日次投稿数**も集計・ランキング表示（A-16）
  - `on_message` 時に投稿者の所持ロールすべてにカウント（Bot・コマンド除外）
  - 投稿数は「そのロール所持者が1日に投稿した回数」の日次集計値のみ保存
- 対象ロールは設定（M-05）で指定（未設定なら全ロール）
- ロールが削除されても閲覧できるよう `role_id` と一緒に `role_name` を保存
- 表示はロール選択（`RoleSelect`）で絞り込み、折れ線グラフで推移を表示

> 性別比率（A-01）も、このロール別メンバー数記録の「性別ロールを特別扱いした
> ビュー」として実装できますが、初回リリースでは専用テーブルで実装します。

## 7. 技術設計方針

### 7.1 設計思想

- **システムコグとして実装**: `utils/system_cogs/analytics_cog.py`（空ファイル）に全機能を実装
- **単一ファイル完結**: コマンド・自動記録ループ・DB操作・グラフ描画を1ファイルに集約
- **自動ロード**: `cultivate_main.py` の `_discover_system_cogs()` が自動検出するため、手動登録は不要
- **既存コマンドとの競合回避**: `cmds/analytics_cmd.py` の `/analytics` は、新実装へ移行後に削除または無効化する（同名コマンドの重複登録を防ぐため）
- **既存 `users` テーブル**: 後方互換のため読み取りは維持しつつ、新規書き込みは `analytics_snapshots` へ移行
- **プレミアム連携**: 有料判定は `Var.PREMIUM_GUILD_IDS`（自動 true）と新規 **Premium登録コグ**
  （`premium_cog.py`）が付与する `premium` フラグで判定。`analytics_cog` は
  **フラグを読み取るだけ**で、付与処理・Premium登録コグの内部実装には依存しない

### 7.2 想定ファイル構成


## 8. パフォーマンス考慮

- スナップショット記録は**1日1回の一括保存**（全ギルド数回転でも負荷軽微）
- イベント駆動のカウントは**メモリ上で集計**し、00:05 に一括で DB へ書き込む
  （メッセージ1件ごとの DB 書き込みは行わない）
- グラフ生成は**リクエスト時のみ**（キャッシュはしない）
- 日次アクティビティは**ユニーク人数のみ保存**（ユーザーID の履歴は保存しない）
- 期間ランキングはユーザー・絵文字ごとの**日次集計値のみ保存**（生ログは保存しない）
- ランク集計は既存インデックス（`idx_guild_preset_chat` 等）を活用
- 招待リンクの差分判定は `on_member_join` 時のみ `guild.invites()` を呼ぶ

### 8.1 データ量の見積もり

前提: **1サーバー200人規模 × 100サーバー**（行サイズは MySQL オーバーヘッド込みで約100バイト）

| テーブル | 1日あたりの行数 | 90日 | 1年 |
|---|---|---|---|
| `analytics_snapshots`（11指標） | 1,100 | 約10MB | 約40MB |
| `analytics_user_daily`（メンション/リアクション） | 4,000 | 約36MB | 約146MB |
| `analytics_channel_posts`（30CH） | 3,000 | 約27MB | 約110MB |
| `analytics_emoji_daily`（30絵文字種） | 3,000 | 約27MB | 約110MB |
| `analytics_role_members`（20ロール） | 2,000 | 約18MB | 約73MB |
| `analytics_role_posts`（20ロール） | 2,000 | 約18MB | 約73MB |
| `analytics_invites`（累計のみ） | — | 微少 | 微少 |
| **合計** | **約15,100行/日** | **約136MB** | **約552MB** |

- 無料サーバー（90日保存）: 約**136MB** / 100サーバー
- プレミアム（全期間・1年）: 約**552MB** / 100サーバー
- MariaDB の容量・性能上は十分許容範囲（インデックスも日次粒度で小さい）

> アクティブ率（メンション/リアクションをする人の割合）は 200人中20人（10%）と
> 保守的に見積もっています。実際はギルドの規模・文化で前後します。
